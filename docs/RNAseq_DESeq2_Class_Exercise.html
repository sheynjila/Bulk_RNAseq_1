How to use this exercise

Work from the project root - the folder containing the RStudio project file. Run the scripts in the stated order. At each checkpoint, record both the command output and a short biological or statistical interpretation.

Do not skip the alignment step: The original CSV headers contain a trailing blank field. The alignment script reads this format deliberately so that SRR1039508 is not dropped and sample labels are not shifted.

Learning objectives

  • Create and maintain a reproducible RNA-seq project structure.
  • Distinguish CRAN packages from Bioconductor packages and install them manually or automatically.
  • Validate and align a gene-count matrix with sample metadata.
  • Build a DESeq2 model that adjusts for cell line while estimating the dexamethasone treatment effect.
  • Interpret DESeq2 result columns, multiple-testing adjusted p-values, and fold-change thresholds.
  • Create and interpret PCA, volcano, heatmap, MA, dispersion, p-value, and gene-expression plots.
  • Run optional log2 fold-change shrinkage, GO enrichment, GSEA, and KEGG Pathview analyses.
  • Export results and plots with enough metadata to reproduce the analysis.

Exercise 5 - Build and run the DESeq2 model

Goal: Fit a treatment comparison that adjusts for differences among cell lines.

Run the model and inspect results
source("scripts/LOAD_CLEANED_ALIGNED_DATA.R")

design(dds)
resultsNames(dds)
summary(res)
head(res[order(res$padj), ])

Understand the design

Model terms used in the script
design = ~ cellline + dexamethasone
contrast = c("dexamethasone", "treated", "untreated")

The cellline term accounts for baseline expression differences among cell lines. The dexamethasone coefficient estimates the treated-versus-untreated effect after that adjustment. Untreated is explicitly set as the reference level.

  • Counts must be numeric, non-negative whole numbers with no missing values.
  • Metadata rows must exactly match count columns.
  • Genes with fewer than 10 total reads across all samples are removed before model fitting.
  • The DESeq2 results use alpha = 0.05 for adjusted-p-value summaries.
Checkpoint question: Why is cellline included in the design instead of using only ~ dexamethasone?
Checkpoint question: What does a positive log2FoldChange mean for the treated-versus-untreated contrast?

Interpret the result columns

DESeq2 results object
Column Meaning Interpretation prompt
baseMeanMean normalized expressionIs the gene lowly or highly expressed overall?
log2FoldChangeEstimated treated/untreated effectPositive is higher in treated; negative is lower.
lfcSEStandard error of the fold changeHow uncertain is the effect estimate?
statWald test statisticHow large is the effect relative to its uncertainty?
pvalueRaw hypothesis-test p-valueEvidence before correcting for many genes.
padjBenjamini-Hochberg adjusted p-valueUse this for the primary significance decision.

Exercise 6 - Summarize and export differential expression

Goal: Count significant genes, separate directions and export a clearly named result table.

Create a DEG summary and export
res_df <- as.data.frame(res)
res_df$gene <- rownames(res_df)

padj_cutoff <- 0.05
lfc_cutoff <- 1

significant <- subset(res_df, !is.na(padj) & padj < padj_cutoff)
up_genes <- subset(significant, log2FoldChange > lfc_cutoff)
down_genes <- subset(significant, log2FoldChange < -lfc_cutoff)

c(total_tested = nrow(res_df),
  significant = nrow(significant),
  up = nrow(up_genes),
  down = nrow(down_genes))

write.csv(
  res_df[order(res_df$padj), ],
  "data/DESeq2_dexamethasone_vs_untreated.csv",
  row.names = FALSE
)
Threshold logic: padj < 0.05 controls the multiple-testing decision. The additional absolute log2 fold-change threshold of 1 identifies changes greater than two-fold in either direction.
Checkpoint question: How many genes meet padj < 0.05? Of those, how many also meet |log2FoldChange| > 1?
Checkpoint question: Why should a raw p-value threshold not be used alone when thousands of genes are tested?

Exercise 7 - Create and interpret the main figures

Goal: Use sample-level and gene-level visualizations to evaluate the experiment and summarize the treatment effect.

Generate PCA, volcano and top-gene plots
source("scripts/VISUALIZE_DESeq2_RESULTS.R")

7A. PCA plot

  • Each point is a sample represented by variance-stabilized expression values.
  • Color represents dexamethasone treatment and shape represents cell line.
  • Inspect whether paired samples are plausible and whether one sample is an obvious outlier.
  • PC axis labels report the percentage of variance explained.
Checkpoint question: Does separation appear stronger by cell line, treatment, or neither? Support your answer using the plot.

7B. Volcano plot

  • The x-axis is log2 fold change; the y-axis is -log10 adjusted p-value.
  • Red points pass padj < 0.05 and log2FoldChange > 1.
  • Blue points pass padj < 0.05 and log2FoldChange < -1.
  • Gray points do not pass both statistical and effect-size thresholds.
Checkpoint question: Choose one up-regulated and one down-regulated gene. Record each gene ID, fold change and adjusted p-value.

7C. Top-gene boxplot

The script selects the gene with the smallest non-missing adjusted p-value, retrieves normalized counts and plots count + 1 on a log10 scale. Jittered points preserve the individual samples and their cell-line identities.

Checkpoint question: Is the top gene's treatment effect consistent across all four cell lines? Describe any heterogeneity.

Exercise 9 - Optional advanced analyses

Run one extension at a time: Set one switch to TRUE, source the additional script, inspect the output, then return the switch to FALSE before testing another extension.

9A. Log2 fold-change shrinkage

Switch in the additional visualization script
run_lfc_shrinkage <- TRUE

apeglm shrinkage moderates unstable fold-change estimates, especially for genes with low information, without redefining the original p-values. Compare the unshrunken and shrunken MA plots.

Checkpoint question: Which genes change most after shrinkage: high-count or low-count genes? What does that imply about uncertainty?

9B. GO enrichment and GSEA

Switch in the additional visualization script
run_enrichment <- TRUE
  • GO over-representation uses Ensembl IDs from genes passing padj < 0.05.
  • The analysis targets Biological Process terms and uses Benjamini-Hochberg correction.
  • GSEA ranks all genes by the DESeq2 Wald statistic and can detect coordinated pathway shifts without a hard DEG cutoff.
  • org.Hs.eg.db supplies human identifier annotations.
Checkpoint question: How does the input to over-representation analysis differ from the input to GSEA?
Checkpoint question: Report one enriched biological process and explain why it may be relevant to the treatment response. Treat this as a hypothesis, not proof of mechanism.

9C. KEGG Pathview

Switch and pathway ID
run_pathview <- TRUE
pathway_id <- "hsa04110"  # Cell cycle example

The script converts Ensembl IDs to Entrez IDs, averages duplicate mappings and overlays fold changes on a human KEGG pathway. Pathview writes its output to plots.

Network dependency: Pathview normally retrieves pathway files from KEGG. This extension can fail when the internet is unavailable or the selected pathway ID is invalid.
Checkpoint question: Why must Ensembl IDs be mapped to Entrez IDs before creating the KEGG overlay?
Why there is no UpSet plot: This project contains one treatment contrast. UpSet plots become useful only when comparing overlapping DEG sets from two or more contrasts.

Instructor and self-check checkpoints

  • The raw alignment stage should retain 64,102 genes and all 8 sample IDs.
  • The metadata should contain exactly cellline and dexamethasone columns after alignment.
  • There should be four cell lines, each represented by one untreated and one treated sample.
  • The DESeq2 design should be ~ cellline + dexamethasone, with untreated as the treatment reference.
  • The primary contrast should be dexamethasone treated versus untreated.
  • The number of genes retained after the total-count >= 10 filter must be recorded from the student's run rather than assumed.
  • Biological conclusions must be based on the generated results; the exercise intentionally does not pre-supply expected DEG or pathway answers.
Completion standard: A technically successful analysis is not only one that runs. It must preserve sample identity, use an appropriate model, document thresholds, pass basic QC review and communicate uncertainty honestly.
